## 第二提交：交互语义

- 范围底栏仅显示刷题 / 背诵题量；全局题型偏好移至组题页，实时更新题量，无可刷题时可“调整题型”。原偏好存储键及实际过滤语义保留。
- 练习方式采用单一“顺序 / 随机”选择，随机数量就近显示。方案直接保存当前方式、类型和数量，不再有第二套默认参数；开始和保存共用数量校验。
- 切换题型保留方式、方案名称和展开状态；题池缩小时随机数量同步收敛至可用上限。目录前进/返回保留本次设置，首页或新选择范围恢复默认参数。
- 目录在点击前明确“从此题开始 / 跳至此题”，条目附有语义名称；不改变创建会话、草稿清空和已提交历史的行为。
- AI 用“格式通过 / 待核对 / 已保存”，保存操作旁明确人工核对和正式题库隔离；费用、取消、重试说明与生成上限保留。
- 验证：交互专项 7 / 7，A 回归 10 / 10，E 回归 9 / 9 通过；包含保存随机 3 题后实际创建 3 题会话、非法数量不保存/不开始、顺序方案不携带随机数量、目录跳转不改变历史统计、AI 不发真实请求。
- 两个初次 UI 测试失败源于测试未等待范围重绘及误选背诵节点为刷题范围；已修正测试等待和合成范围，再通过。未因此改动生产数据逻辑。
- `.local-workflow/build-my-release.ps1` 第二次构建通过，独立检查版本 0.1.12 / 113、应用 ID com.kehai.knoop、仅 ARM64；签名 v2/v3 与 strip 验证通过。日志 `artifacts/review-ui/release-step2.log`。

## 第三提交：层级与可访问性

- 首页突出继续 / 新练习，四项计数为轻量元数据，最近方案为轻量行；错题、收藏为次级动作，低频功能弱化。真正空数据首页只有导入。若正式题库已删除但仍有 AI 题组、草稿或任务，则继续保留其入口，避免隐藏现存内容。
- 答题页收藏、笔记直达；编辑、斩杀、标记问题纳入原生 details 的“更多”，支持键盘展开。保留斩杀确认与可恢复信息。
- 正式与 AI 选项结果加入 ✓ 选对 / ✕ 错选 / ✓ 漏选 / ✓ 正确答案；选择状态含 aria-pressed，答案预览也显示文字标识。保持原判分和数据库写入。
- 新触控区域至少 48px；桌面视口 320 / 360 / 390 / 480 和横屏大字截图检查通过。未使用新 UI 框架、底部导航或整体重构。
- 本地提交顺序：`040fb80` 文案及版本；`26d9fa5` 交互语义；第三提交为本文件所在的最终 HEAD。
