# 接口兼容与 AI 学习闭环约定

## 1. 两个接口的方向

```text
knoop-bank 1.0 / 1.1
AI / 人工 ------------------> 刷题器

knoop-error-review 1.0
刷题器 ---------------------> AI
```

不要把两者混用。

`error-review` 是诊断输入；AI 处理完成后必须重新生成正常 `knoop-bank`。

---

## 2. 推荐闭环

```text
教材 / 用户重点
    ↓
AI 检索与出题
    ↓
knoop-bank
    ↓
刷题器
    ↓
Attempt
    ↓
当前错题
    ↓
knoop-error-review
    ↓
AI
├─ 判断原题质量
├─ 分析错误模式
├─ 修订原题
├─ 生成变式题
└─ 生成定向训练
    ↓
knoop-bank
    ↓
merge / new
```

背诵材料走同一题库入口：

```text
简答 / 重点段落 / 英语范文
    ↓
knoop-bank 1.1
    ↓
memorization
    ↓
背诵模式
```

---

## 3. 变式题的质量原则

“变式”不是简单同义改写。

高价值变式应保持核心知识点不变，同时改变至少一种知识调用条件：

- 场景；
- 设问角度；
- 条件组合；
- 正问 / 反问；
- 干扰项来源；
- 概念边界；
- 推理顺序；
- 信息冗余；
- 典型误区。

目标是检验：

> 用户是否掌握可迁移的判别规则，而不是记住原题外观。

AI 应结合：

- `wrongSelected`
- `missedCorrect`
- `wrongCount`
- 原解析
- 题目所属 Node

设计定向变式。

---

## 4. 原题修订与变式题 ID

### 修原题

如果确认只是原题本身有问题，并希望覆盖本地原题：

- 保留原 `question.id`
- 使用 `import.mode = "merge"`

### 变式题

必须使用新的稳定 ID。

推荐：

```text
<原知识点前缀>-var-001
<原知识点前缀>-var-002
```

不要复用原题 ID，否则会覆盖原题。

可以增加标签：

```json
"tags": [
  "变式题",
  "定向训练"
]
```

当前不强制新增 `origin` 字段。

---

## 5. `source` 字段

当前刷题器的数据模型已经允许保存：

```json
"source": ...
```

本规范将其视为 **不透明 JSON 元数据**：

- AI 可以提供；
- 刷题器应保存；
- 客户端不需要理解所有内部字段；
- 未知字段不得被擅自改写。

如果出题项目已有独立来源 sidecar，也可以继续使用 sidecar。

两者不是强制替代关系。

---

## 6. 版本矩阵

| 文件 | 旧客户端仅支持 1.0 | 新客户端支持 1.0 + 1.1 |
|---|---:|---:|
| bank 1.0 | 可导入 | 可导入 |
| bank 1.1 | 可拒绝 | 必须可导入 |
| error-review 1.0 | 不导入 | 不导入；只用于导出/AI |

`knoop-error-review` 永远不是题库导入格式。

---

## 7. JSON 字符编码

所有文件：

- UTF-8；
- 推荐无 BOM；
- JSON string 中换行使用标准转义 `\n`；
- 时间使用 ISO 8601 / RFC 3339，例如：

```text
2026-09-21T16:30:00+08:00
```

或：

```text
2026-09-21T08:30:00Z
```

---

## 8. 客户端实现优先级

0.1.0 Alpha 建议按：

1. 接受 bank 1.0 / 1.1；
2. 导入、保存、显示 `memorization`；
3. 背诵模式；
4. `recall` / `memorization` 快刷直接显示内容；
5. 导出当前错题 error-review；
6. 选择题长按排除。

接口本身不依赖长按排除功能，因此不记录用户排除过哪些选项。
