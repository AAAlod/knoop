## 目标与基线

现阶段把 Knoop 做成适合 Android 墨水屏持续学习的工具，首个目标为汉王 Clear6 Plus（PA6 / PA6GB32）。通用 Android 手机和平板适配依照 README 延后到 2027 年。

- 真机：758 × 1024，260 dpi，Android 11，WebView `83.0.4103.120`。本轮重新查询确认设备在线、密度和 WebView；已安装版本为 `0.1.12 / 113`。
- 上一轮已验证安装、题库导入、基础作答、公式局部横向滚动及学习状态保存，见 [兼容性记录](pa6-compatibility-validation.md)。这些是兼容基线，不能视为墨水屏体验验收。
- 本轮新检查：首页、继续进入第 27 项背诵卡、展开更多、滚动查看更多操作、进入编辑后不保存返回。更多操作经滚动可达，并非完全不可用。
- 本地截图位于 Git 忽略的 `artifacts/pa6-validation/`：`eink-review-current.png`、`eink-review-recall.png`、`eink-review-more.png`、`eink-review-more-scrolled.png`、`eink-review-editor.png`、`eink-review-return.png`。
- 758 × 1024 是物理像素。260 dpi 下可用 CSS 视口更小；实施时测量实际 `innerWidth / innerHeight` 和键盘出现后的视口，不能按 758 CSS px 设计。

## 适配方案

### 1. 默认采用墨水屏视觉规范

当前主线直接使用墨水屏样式，无需新增设备型号选择或让用户手动开启适配。

- 页面、卡片、顶栏和底栏使用纯白不透明背景，正文优先黑色，次级内容用较深灰；移除装饰阴影和浅色底纹。只对少量主操作使用黑底白字，避免整页大面积反色。
- 通过标题、字重、间距和黑色边框建立层级。颜色不承载唯一语义；“选中 / 排除 / 不可用 / 选对 / 错选 / 漏选”能在黑白画面区分。状态变化尽量不改变选项高度。
- 首轮保留现有学习入口与操作语义，整理留白和字级；题干约 20–22 CSS px，正文约 16–18 CSS px 作为起点，以真机可读性调整。交互区域至少 48 CSS px，不能为塞进一屏缩小触控目标。
- 字体调整后仍可阅读完整内容，公式保留本地 KaTeX 与独立横向滚动。禁止用全页灰度滤镜或图片化文本实现黑白主题。
- 原生启动背景、系统栏、键盘前后窗口边距一并检查。目前 Android 主题为 DayNight，需验证系统深色模式是否影响 WebView 和系统栏，再决定必要的原生调整。

样式实现先统一基础色值和尺寸变量，墨水屏规则集中维护；若拆出 `src/eink.css`，使用普通 CSS 并在实际构建与测试中一起加载，不使用 Chrome 83 不支持的 CSS 分层语法，不继续散落追加版本覆盖规则。

### 2. 阅读操作与答题操作分离

首先把底栏、菜单和滚动修好，再加入按屏阅读。首轮不引入复杂的自动拆题或整本文档排版。

- “上屏 / 下屏”只移动当前内容；相邻屏保留少量重叠文本，直接定位而不平滑动画。到边界时状态明确。
- “下一题 / 下一项”才推进会话并写入进度；阅读翻屏、公式横向查看和展开解析均不提交、不判分、不新增会话。
- 测量可用高度时扣除顶栏、底栏和软键盘；横竖屏、字号及公式渲染变化后重新计算。超长段落和公式不丢内容，原有手动滚动继续可用。
- 显示答案与解析时维持上下文；进新题回页顶；从笔记 / 编辑返回恢复题目阅读位置。正式会话和 AI 临时题组遵守相同规则，保留各自数据隔离。
- 本轮没有验证 PA6 物理翻页键及其按键码。实体键映射在确认设备输入后另做，不能预设音量键或某个键码就是翻页键。

### 3. 减少不必要的界面更新

保留现有选项局部更新和持久化队列，先处理会重复整页渲染的常见动作、短暂提示及搜索中间状态。关键失败需要可读、可重试，操作忙碌时仍能辨识文字。只在内容或状态改变时更新对应区域，不加入滚动动画、闪烁光标以外的装饰动画或持续刷新的计数。

软件更新次数与墨水屏硬件刷新次数分别记录，不以截图或 DOM 更新次数宣称降低了残影、闪烁或功耗。

### 4. 厂商刷新控制作为独立探索

仓库应用层尚无汉王刷新接口或对应 SDK 接入。本轮没有获得足以确认适用于此固件的官方接口资料。

后续先确认可用 SDK、设备与固件范围、授权及接口行为，再做最小原生桥验证，评估局刷 / 全刷触发点。失败时继续使用系统刷新行为；没有可靠接口时，首轮视觉与交互适配仍可交付。重绘 WebView、黑白遮罩切换或 CSS 反色不能冒充硬件全刷。实体残影、闪烁、刷新时延需要观察实际显示屏。

## 实施顺序与交付边界

| 阶段 | 工作与主要文件 | 通过标准 |
| --- | --- | --- |
| M1：可读且可靠的墨水屏基础版 | R1–R6、R10；`style.css`、必要的集中主题样式、`main.ts` 的壳层 / 表单 / 搜索 / 状态标记、`index.html`，必要时 `MainActivity.kt` 和 Android theme；同步 UI harness。 | 首页、选范围、选择模式、各题型、答案与更多菜单具备黑白状态；底栏不透字；最后输入区与操作可达；Flex 间距、搜索忙碌禁用和焦点回退在 PA6 有效。产出可覆盖安装的签名 ARM64 Release 与新的设备验证记录。 |
| M2：按屏阅读与稳定上下文 | R7–R8；引入小范围的阅读定位模块，接入正式题目、背诵和 AI 临时练习，修复顶栏与返回位置。 | 长题 / 长背诵可上屏下屏阅读，内容无遗漏；翻屏不写作答；下一题回顶部；显示答案和来回编辑保持合理位置；字号、键盘与横屏变化后仍可达。 |
| M3：更新与反馈优化 | R9，目录大题量与离线 AI 页面；只对有观察依据的路径做局部更新。 | 连续操作无重复提交，草稿与进度可恢复；错误提示可读可关闭；搜索不会跳旧结果；已有公式、统计、笔记和 AI 隔离回归通过。实物刷新表现单独记录。 |
| M4：原生刷新与实体键探索 | 取决于可靠接口资料与设备输入验证，不阻塞 M1。 | 明确接口支持范围和降级方式；能在实际屏幕观察结果后再决定是否纳入发布。 |

M1 是下一步实施范围。M2–M4 逐步推进，不承诺在一个包内完成；现有兼容修复作为基础保留。首轮不新增题库协议、数据库迁移、云同步或 AI 在线调用，也不默认新增需要备份协议变更的阅读偏好。

## 验收矩阵与检查入口

| 场景 | 需要验证的结果 |
| --- | --- |
| 首页、范围和模式 | 空数据 / 有继续进度均可用；主动作明确；四项计数、大字换行、黑白题型开关及 0 题状态清楚。空数据场景在隔离环境检查，不能清除用户设备数据。 |
| 单选、多选 | 选择、取消、排除、提交、错选及漏选均无需辨色；长按不会误提交；快刷语义保留，忙碌时不重复写入。 |
| 填空、笔记、编辑、审核 | 键盘开 / 关、最后字段、底栏换行和提交失败反馈；草稿可保留，返回路径正确。真机现有内容不随意保存修改，写入场景用合成数据。 |
| 长题、公式、背诵 | 全部内容可达，公式局部横向查看不带动整页；答案与解析可读；M2 再检查按屏阅读和位置恢复。 |
| 目录和列表 | 搜索忙碌状态不能点击 / 键盘确认旧结果；展开更多和错题详情不被底栏挡住；大题量与大字下可操作。 |
| AI 临时题组 / 草稿 / 批次 | 使用隔离的离线合成数据检查黑白状态与操作，保留格式通过、人工核对与费用说明；不因此发出真实 AI 请求，不污染正式统计。 |
| 安装与恢复进度 | 同签名 `adb install -r`，不卸载、不清数据；冷启动保留题库、历史答案、草稿、收藏 / 笔记和未完成进度。 |
| 实体屏观察 | 分别观察选中、提交、翻题、长页阅读、键盘开关与连续使用后的残影 / 闪烁 / 等待感。截图结果和用户观察分别记录，未观察项标为未验证。 |

每个涉及应用代码的阶段均执行：

1. 运行 `rtk proxy npm run check:ci`，再运行对应交互专项。涉及 UI 时必须包含修正后的 `test:review-ui` 或相应墨水屏行为测试；现代浏览器截图仅用于补充。
2. 运行 `rtk proxy pwsh -NoProfile -File .local-workflow/build-my-release.ps1`，核对实际版本、ARM64、签名和输出 APK，并核对摘要。版本变更时遵守现有元数据一致性检查。
3. 按 [PA6 视觉工作流](pa6-visual-workflow.md) 覆盖安装，进入变更场景获取新截图；保存相关数据的场景冷启动复测。
4. 验证记录写入 `docs/`：区分本轮新测、沿用基线、未测与实体屏观察。设备离线时明确“PA6 真机未复测”。

本轮仅形成 Review 与计划，检查入口为 `check:repo` 与 `git diff --check`；未重新执行应用回归测试或签名 Release 构建。README 保留公开产品介绍和路线，本计划及设备操作记录留在开发文档中。
